# 账号与学习空间

登录、注册、访客与数据隔离使用同一套实现；本地数据和线上数据分别保存，不会随代码发布互相覆盖。

## 入口

- `/login` 可切换登录和注册。注册使用昵称、邮箱、8–128 位密码；密码须包含大写字母、小写字母、数字、特殊符号中的至少 3 类，空格不计入字符类别。成功后直接进入自己的空间；已有账号登录不受新注册密码规则限制。
- 当前 `PRIVATE_OWNER_EMAIL` 保留给原私人账号，不能通过注册占用。原远程私人登录继续使用现有服务器。
- 游客进入自带概率论示例，不复制私人资料。会话 2 小时失效；过期文件在后续进入时回收，并为已有处理任务留出 10 分钟完成时间。AI 请求在游客空间中拒绝。
- 游客创建最多同时进行 2 个，暂存空间上限 32 个；达到容量时可稍后重试或注册账号。

## 存储

- 认证继续使用 `DATABASE_URL` 对应的主库；原私人账号的学习数据和文件保持原位置。
- 普通账号：`DATA_DIR/workspaces/users/user-<账号ID的SHA256>/learning.db` 及同级文件目录。
- 游客：`DATA_DIR/workspaces/guests/guest-<游客ID的SHA256>/learning.db`，同级 `guest.json` 记录到期时间。
- 未设置 `DATA_DIR` 时使用项目的 `data`。新学习库从主库复制表结构和索引，不复制数据。
- 学习 API、文件读取和后台任务使用当前空间；LocalStorage、SessionStorage 和笔记 IndexedDB 同样隔离。主题作为浏览器偏好共享，原私人账号可继续读取旧草稿键。
- 账号变化会通知同源的其他标签页刷新。浏览器学习请求携带空间标识，服务器拒绝旧标签页向新身份写入。
- 普通账号和游客的学习写请求必须携带匹配的空间标识；仍允许旧版站主页面保存站主自己的数据。

## 本地与部署

- 使用远程私人登录的本地预览可另外注册本地账号。没有本地 `BETTER_AUTH_SECRET` 时，仅开发模式会生成 `data/.local-auth-secret`；它不进入 Git。
- 生产始终需要显式配置 `APP_URL` 和 `BETTER_AUTH_SECRET`。本地新账号不会自动出现在现有线上服务。
- 后续部署须保留主认证库及整个 `workspaces` 目录，不能用本地数据库覆盖已经使用中的线上数据。
- 更新 Prisma 结构时，应对已有账号的 `learning.db` 执行相同的非破坏性结构迁移。备份前停服；现有完整目录备份会包含这些库和文件。
- 这批改动没有发送验证邮件或新增找回密码流程。
- 原 `scripts/private-cloud-check.mjs` 面向禁止注册的旧单用户版本；本次账号入口发布使用 `work/login-release-20261026/` 中记录的新验收，避免套用旧断言。
